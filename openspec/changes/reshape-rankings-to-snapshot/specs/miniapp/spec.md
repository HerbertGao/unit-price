## 修改需求

### 需求:miniapp 必须是消费 /rankings 的只读榜单小程序骨架

`/rankings` 改为全量快照后,端上消费口径随之改形:榜单/搜索/下钻榜数据**必须**通过 `@unit-price/api-client` 的 `buildRankingsUrl` + **`parseRankingsSnapshot`** 消费 `GET /rankings`(单参、`jitless` 已内置),`parseRankingsResponse` 随旧数组形状一并消失。即时比价仍走 `buildComputeUrl` + `parseComputeResponse`。网络层仍用 `Taro.request`。

**只读边界不变**:禁止扫码 / 拍照 / 贡献 / 纠错 / 写库入口;端上不跑 tier1 解析或单价计算。唯一的写形请求仍是 `POST /compute`。

**请求次数改变**:一次页面挂载取一份快照,cohort 切换 / 翻页 / 搜索**不再发任何请求**——它们是同一份对象上的本地派生。`分类` Tab 仍只读消费 `GET /categories`;其下钻榜**不再**发起 `GET /rankings?category=<slug>`。

#### 场景:浏览只读、即时比价不在端上计算

- **当** 检查端上代码路径
- **那么** 不得出现扫码 / 拍照 / 贡献 / 纠错 / 写库入口;不得在端上跑 tier1 解析或单价计算
- **那么** 派生视图(cohort 过滤 / 搜索 / 切片)是纯本地操作,**不构成**端上计算单价——它们不产生任何新的 `per100ml`

#### 场景:三个底部 Tab 且边界不变

- **当** 检查底部 Tab
- **那么** 仍为 `榜单` / `分类` / `我的` 三个,各自边界不变

#### 场景:经 api-client 消费 /rankings

- **当** 端上取榜单数据
- **那么** 必须用 `buildRankingsUrl` 构造 URL、`Taro.request` 发请求、`parseRankingsSnapshot` 校验响应;**禁止**手写重复的响应类型或绕过校验
- **那么** `parseRankingsResponse` 不得再被引用——它已随旧数组形状移除

#### 场景:miniapp 不进根 tsc -b reference 图

- **当** 跑根 `tsc -b`
- **那么** miniapp 不在 reference 图内,其类型检查由自身构建承担

### 需求:榜单一屏必须支持分页与加载/空/错三态

分页**必须**支持:**下拉刷新**(重取快照并重置到第一屏)+ **触底加载**(揭示下一段本地切片,直到切片耗尽即到底)。分页是**本地切片**,不发请求。

三态**必须**明确:**loading**(首次加载有指示)、**空**(无入榜项时显示空态而非空白或报错)、**错误**。

**两个错误位收敛为一个**:原「首屏错 vs 翻页错」的区分建立在「翻页是一次网络请求、会失败」之上。本地切片不会失败,故**翻页错不再存在**,一并删除其局部重试入口——一个永不可达的重试按钮不是防护网,它只是读起来像。剩下的唯一错误位是**首屏错**(快照 fetch 或其校验失败且屏上无数据 → 整屏错误态 + 重试入口)。任一错误态**禁止**白屏或渲染脏数据。

**落地 cohort 是具名常量 `LANDING_COHORT`,不是推导结果**。调用方未指定 cohort 时用它。**禁止**改为「从树上推导最浅的单一可比轴节点」——该规则无唯一解(`soft-drink` 与 `dairy` 同为 root 直子且同为 `per_100ml`),实测会落到乳品榜。它**必须与榜标题文案(`SCOPE_TEXT`)指同一 cohort**:标题本就是常量,只推导 slug 才是两者能对不上的原因;二者不一致时用户会在写着 A 的标题下看到 B 的榜。**唯独** taxonomy 未播种(树为空)时该常量不在树中,那是合法退化态、走空态,不得判为未知品类。

**空态必须区分「暂无数据」与「该 cohort 无法开榜」**:目标节点跨多个可比口径、或 slug 不在树中时,派生被拒绝。此时**禁止**沿用「下拉刷新试试」文案——下拉永远不会让它有数据。**唯独** taxonomy 未播种(树为空)是合法退化态,按普通空态呈现,不得报成「该分类不存在」。

**触底揭示不得被后台重验打断**:命中缓存后的后台重验成功时**禁止**重置已揭示的切片长度,否则用户正在滚动的列表会在手指下弹回第一屏。下拉刷新与首屏重试**必须**重置。

#### 场景:升序榜单与字段渲染

- **当** 渲染榜单行
- **那么** 按 `per100ml` 升序呈现,序取自服务端下发、端上不重排;字段渲染口径不变

#### 场景:下拉刷新与触底分页

- **当** 用户下拉刷新
- **那么** **必须**重取快照、重置到第一屏切片
- **当** 用户触底
- **那么** **必须**揭示下一段本地切片、**不得**发起请求;切片耗尽即到底
- **当** 命中缓存后的后台重验成功返回
- **那么** **禁止**重置已揭示的切片长度

#### 场景:加载/空/错三态（首屏错与翻页错分开）

- **当** 首次进入加载期间
- **那么** **必须**有 loading 指示
- **当** 快照为空或派生视图无行
- **那么** **必须**显示空态,不得空白或报错
- **当** 首次加载 `/rankings` 失败或 `parseRankingsSnapshot` 抛错且屏上无数据
- **那么** **必须**整屏错误态 + 重试入口
- **当** 用户触底翻页
- **那么** **不存在**翻页错误位:本地切片不会失败,故**禁止**保留翻页错误态与其局部重试入口
- **当** 目标 cohort 跨多个可比口径,或其 slug 不在树中
- **那么** **必须**呈现与「暂无数据」可区分的说明,**禁止**提示下拉刷新
- **当** taxonomy 未播种(树为空)
- **那么** 按普通空态呈现,**不得**报成「该分类不存在」

### 需求:搜索入口为真输入、跳转复用 board 列表页

顶部搜索入口**必须**仍为**真输入**:用户输入商品名后跳转复用 board 列表页。**但搜索不再发起请求**——它是当前 cohort 内对已持有快照的本地子串筛选,口径由 `api-client` 单方定义(`trim` → **有效码点数 < 2 则匹配空集** → 按码点截断 ≤64 → 仅 `A-Z`↔`a-z` 折叠 → 子串),端上**禁止**另写一份匹配规则。

**搜索的 cohort 必须显式**:落地页的搜索继承 `LANDING_COHORT`(定义见「榜单一屏必须支持分页与加载/空/错三态」需求),不得在无 cohort 的情况下搜索——那会退化成对某个任意 cohort 的搜索。深链或手输的 `board?q=…` 若未带 cohort,同样按 `LANDING_COHORT` 处理,不得渲染无 cohort 的结果。

搜索**仍不构成**贡献 / 纠错路径。

#### 场景:输入商品名后跳转复用 board 列表页搜索

- **当** 用户在搜索框确认输入
- **那么** 跳转 board 列表页并带上搜索词与所属 cohort;**不得**发起网络请求

#### 场景:board 标题按来源派生

- **当** board 页由搜索进入
- **那么** 标题按搜索词派生;由分类下钻进入时按品类派生

#### 场景:含 % / & 的搜索词逐字节往返不变

- **当** 搜索词含 `%` / `&` / `_` / `!`
- **那么** 按字面量匹配,不做通配解释;因不再有 URL 往返,原「逐字节往返不变」由「本地匹配不改写词」承载

#### 场景:空输入或单字不发起请求

- **当** 输入为空或有效码点数 < 2
- **那么** 不进入搜索态。原「不发起请求」在快照形态下恒成立,该门的作用改为**防止单字命中几乎整个 cohort**
- **当** 这样的词仍经深链或手输抵达列表页(入口拦不住它)
- **那么** 必须**匹配空集**,不得落回「不过滤」而端出整个 cohort——页面标题此时写着「搜索:X」,端出全量等于宣称每一行都命中了该词

### 需求:分类 Tab 必须以只读品类树呈现并可下钻到 category-scoped 榜

`分类` Tab 仍**仅**发起只读 `GET /categories` 呈现整树。其下钻的 category-scoped 榜**不再**发起 `GET /rankings?category=<slug>`,改为在同一份快照上按该节点本地过滤。

可点性判据不变:必须只用 `node.rankable`;节点契约中不再存在 `rankableCount`。

若界面将来需要展示某节点的实际榜行数,必须从当前持有的同一份快照按该节点派生后计数,不得请求或重建服务端节点计数。当前分类树不展示数量徽标。

#### 场景:经 api-client 只读消费 /categories

- **当** 分类 Tab 取树
- **那么** 必须用 api-client 的 categories 契约,只读、不写库

#### 场景:可点性由 rankable 闸口

- **当** 判定某节点是否可点进
- **那么** 必须只用 `node.rankable`;categories 与快照节点 schema 均不得暴露 `rankableCount`

#### 场景:节点数量只从同一快照派生

- **当** 界面需要展示某节点的实际榜行数
- **那么** 必须从当前快照按该节点派生并计数,不得使用独立服务端计数字段

#### 场景:下钻 category-scoped 榜

- **当** 用户点进一个 `rankable=true` 节点
- **那么** 该榜必须由端上在快照上按该节点过滤得出,**不得**发起 `GET /rankings?category=<slug>`
- **那么** 归属判据是「行的任一 `categorySlugs` 是该节点或其后代」,对叶与非叶一致

#### 场景:未播种 taxonomy 的空态

- **当** taxonomy 未播种
- **那么** 分类树与快照同为空,呈现空态、不报错

### 需求:榜单首屏必须经端上 SWR 缓存即时回显并后台重验

**缓存范围与键**:缓存**整份快照**,键为**单一固定字面量**(不再按 cohort 分键)。cohort / 搜索 / 翻页都是同一份对象上的本地派生,分键会缓存同一份数据的多个副本。原「搜索与翻页禁止缓存」的规则随之消失——它防的是「缓存了一个过滤后的子集却当全量用」,而现在缓存的就是全量。

**换键而非兼容旧值**:旧键存的是 `RankingsItem[]`(数组),过不了新的对象 schema。换用新键保证正确性;清理旧键**仅**为回收端上存储配额,不是正确性手段。

**读即重校验**:读缓存**必须**经 `parseRankingsSnapshot(raw)` 重新校验(单参);损坏 / 旧 schema 残留 → **必须**视作未命中,**禁止**渲染未校验脏数据。

**无 TTL 是已知接受项**:缓存不带生成时刻,故命中时呈现的可能是任意旧的快照,直到后台重验回来覆盖。SWR 的即时回显是它的对价。

#### 场景:命中缓存即时回显 + 后台刷新覆盖

- **当** 端上存有可通过校验的快照
- **那么** **必须**立即回显、不进整屏 loading,并在后台重取覆盖

#### 场景:命中后触底翻页不重复首页

- **当** 命中缓存后用户触底
- **那么** 揭示下一段本地切片;因整份快照已在手,**不存在**「重复请求首页」的可能
- **那么** 后台重验成功时**禁止**把已揭示长度重置回第一屏

#### 场景:有缓存时后台重验失败保留旧数据

- **当** 命中缓存后后台 fetch 或 `parseRankingsSnapshot` 校验失败
- **那么** **必须**保留已回显的旧数据,不得回退整屏错误态

#### 场景:缓存缺失回落既有三态

- **当** 无缓存或缓存校验失败
- **那么** 回落 loading → ready / 空 / 首屏错三态

#### 场景:仅缓存非搜索首页

- **当** 检查写缓存的时机
- **那么** 写入的**必须**是整份快照本身,与当前 cohort / 搜索词 / 已揭示长度无关;**禁止**缓存任何派生后的子集

## 新增需求

### 需求:api-client 必须提供榜单快照契约与端上派生能力

`packages/api-client` **必须**提供快照端点的**传输无关**契约(Zod schema + 推导类型 + URL 构造 + 解析函数),形态**必须**与既有 `rankings` / `categories` 契约一致:解析函数**只接 `json` 一个入参、内部硬编码 `{ jitless: true }`**(**禁止**把 `jitless` 外露成调用方可选项——漏传会在禁 `eval` 的运行时因 JIT `new Function` 崩溃),校验失败**必须**抛 `ZodError`(原样冒泡、fail-closed),**禁止**返回未校验或部分数据。

快照行 schema **必须**按引用复用既有 `RankingsItemSchema`(在其上增加叶品类 slug),**禁止**另写一份重复定义。新增字段**必须**设 `.optional()`,理由与既有 `capturedAt` / `lowestPriceCents` 一致:共依赖同一 schema 的独立发布客户端要容忍跨版本旧服务端与 CDN 缓存的旧响应,设必填会在每次改 schema 的部署后制造最长一个 TTL 的整屏错窗口。

本包**必须**提供从快照派生各视图的能力——**排序、按品类过滤、分页、按商品名子串搜索**——使调用方**不必**自行实现这些口径:

- **排序**:按 `per100ml` 升序;`per100ml` 相等时**必须**用确定性 tie-breaker,口径与服务端一致。端上**只排序,禁止重算 `per100ml`**(它是服务端存储值)。
- **品类过滤**:入参为品类 slug 与 `/categories` 的树;**必须**沿 `parentSlug` 判定祖先归属,使点祖先节点得到其全部后代的合并结果。
- **跨 cohort 拒绝**:目标节点 `comparableUnit` 为 `null`(跨多个可比口径)时**必须**拒绝派生视图并给出可呈现的原因,**禁止**把不同轴的数字混排。该判定是**同口径的前置拦截**,服务端的权威守卫**不因此撤除**。
- **搜索**:子串匹配口径(大小写、全角/半角)**必须**与服务端 `GET /rankings?q=` 一致,否则同一个词经深链与经端上搜索得到不同结果。
- **分页**:对已排序已过滤的结果切片,并按 `offset + 1-based index` 赋 `rank`,与 `/rankings` 的 `rank` 语义一致。

本包**仍**只依赖 `@unit-price/core` 与 Zod,**禁止**依赖任何运行时 / 框架包。既有 `rankings` / `categories` 契约**不变**。

#### 场景:快照解析函数与既有契约同形态

- **当** 调用方解析快照响应
- **那么** 解析函数**必须**只接 `json` 一个入参、内部以 `{ jitless: true }` 校验;不满足 schema 时**必须**抛 `ZodError`(fail-closed),**禁止**返回未校验或部分数据

#### 场景:快照行复用 RankingsItemSchema 且新增字段可选

- **当** 定义快照行 schema
- **那么** **必须**按引用复用 `RankingsItemSchema`,**禁止**重复定义字段;新增的叶品类 slug **必须**设 `.optional()`,使旧服务端响应或缓存的旧响应仍能解析通过而非整屏 ZodError

#### 场景:按祖先节点过滤得到全部后代

- **当** 以一个非叶但单一可比口径的品类 slug 过滤快照
- **那么** 结果**必须**包含其**全部后代叶品类**的行(沿 `/categories` 的 `parentSlug` 判定),而不仅是直接子节点的行

#### 场景:跨 cohort 节点必须被拒绝而非混排

- **当** 以一个 `comparableUnit` 为 `null` 的节点(如 root `饮料`)过滤快照
- **那么** **必须**拒绝并给出可呈现的原因,**禁止**返回把不同可比轴的数字并列的结果

#### 场景:端上排序不重算单价

- **当** 派生任意排序视图
- **那么** 排序键**必须**取自快照行已有的 `per100ml` 存储值;**禁止**在端上重算单价或改写该值

#### 场景:per100ml 相等时次序可复现

- **当** 两行 `per100ml` 相等
- **那么** 二者先后**必须**由确定性 tie-breaker 决定,重复排序结果相同,且与服务端 `/rankings` 的口径一致

#### 场景:本地搜索与服务端 q 同口径

- **当** 同一个搜索词分别经端上搜索与 `GET /rankings?q=<词>`
- **那么** 命中集合**必须**一致(大小写、全角/半角处理同口径);**禁止**两侧各自实现导致深链与端上结果不同

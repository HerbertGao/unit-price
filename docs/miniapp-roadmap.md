# 小程序当前状态与后续路线

> 本文是 `apps/miniapp` 产品状态的单一事实源。网络与数据契约以 OpenSpec 主 `miniapp` spec 为准，视觉规则以 [`apps/miniapp/DESIGN.md`](../apps/miniapp/DESIGN.md) 为准。

## 当前实现

运行时为 Taro 4.2.1 + React 18.3.1，构建前会机械检查 React peer 兼容性。

| 页面 | 已实现行为 |
| --- | --- |
| 榜单 Tab | 软饮落地榜、商品名搜索、下拉刷新、本地触底切片 |
| 分类 Tab | 品类树；只允许 `rankable` 节点进入本地派生榜 |
| 我的 Tab | 结构化即时比价入口、本地最近记录、来源说明、微信反馈 |
| board 页 | 分类下钻或搜索结果 |
| compute 页 | 结构化规格提交、服务端计算、同 cohort 位置与邻居 |

数据行为：

- 页面挂载取一份 rankings 快照；cohort、搜索和分页不再请求服务端。
- 快照使用 SWR 单键缓存，读取时重新做共享 Zod 校验。
- 端上不运行 core；即时结果来自无状态 `/compute`，且不写中心库。
- 30 天以上未重报的榜单行置灰但不改变单位价排序；现价高于最低正价时显示历史低价。
- 空树、未知节点、不可排名节点和网络失败使用不同状态，不用“刷新试试”掩盖永久拒绝。

## 尚未实现

- attribute 复合筛选、收藏
- 商品详情页和商品图片
- 采集日期、全局新鲜度横幅、自动刷新
- 扫码、拍照、OCR、自由文本 parse
- 贡献入库、人工纠错、账户与跨设备历史

这些能力没有隐藏入口，也不得从旧归档提案推断为现状。

## 下一步

### 新鲜度闭环

- 建立山姆软饮重抽与 ingest 节奏
- 在行内显示采集日期和“可能已变动”说明
- 保持单位价纯排序，不引入不可解释的综合分

### 商品信任页

- 展示规格、formula、warnings、同 cohort 位置和低样本提示
- 图片继续延后；无图时保持文字优先

### 纠错与贡献

- 先定义 `/corrections` 的身份、滥用控制和人工处理闭环
- 只有在中心库确需接收小程序写入时再新增贡献流程
- 只有明确用户流需要时才接入自由文本 `/parse`，不在端上复制 core

## 条件成熟再做

- R2 商品缩略图与总开关/删除机制
- 第三方公众 API
- 浏览器插件、多商店、复杂品类

发布平台的审核、上架和推广状态属于外部运营记录，不在本文件维护。每项新能力独立走 OpenSpec。
